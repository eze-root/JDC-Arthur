# 刷机前确认与 AP 模式

先阅读[连接、存储、编译与升级流程](arthur-operations.md)。本项目目标是 JDCloud RE-SS-01；型号、分区与引导状态必须从实机确认。

旧版本文把“进入引导界面、先刷 factory、再刷另一个包”简写为通用步骤，缺少对已有引导版本和镜像类型的限定，因此不再作为直接操作指令。已经运行 OpenWrt 的设备通常不需要重刷 U-Boot。只使用当前型号和固件明确支持的升级路径，不能混用其他京东云型号的引导程序或镜像。

## 纯 AP 模式与代理路由模式

纯 AP 用于无线接入与二层桥接，管理 IP 应在上级 LAN 内且避开 DHCP 地址池，DHCP 服务通常由上级承担。先确定上级网关、DNS 和地址池，再关闭本机 DHCP，保留可访问的管理 IP。

不要直接删除全部非 LAN 接口；先记录现状，并保留管理通道。电脑直连已关闭 DHCP 的 AP 时，可能需要临时静态 IP，这也是出现 169.254.x.x 的原因之一。

如果需要本机为客户端执行透明代理，客户端流量必须实际经过本机的路由路径。主路由模式应保留本机 LAN DHCP；纯 AP 并不自动满足这个条件。详见 [sing-box 配置](singbox-tproxy.md)。
